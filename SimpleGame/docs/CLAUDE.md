# CLAUDE.md — SimpleGame (BaseProject_SE)

이 문서는 본 프로젝트의 개발 지침이다. 코드 작업과 기획 작업 모두 이 문서의 결정을 기본 틀로 삼는다.

---

## 1. 프로젝트 개요

- **과목**: 한국공학대학교 Game Software Engineering
- **베이스**: 교수 배포 템플릿 (Lee Taek Hee, Tech University of Korea)
- **기술 스택**: C++ / OpenGL / freeglut / GLEW, Visual Studio 솔루션 (x64)
- **최종 목표**: 실시간 렌더링 기반의 **오픈월드 RPG**
- **표현 방식**: **쿼터뷰(아이소메트릭) 2.5D**
- **플레이 형태**: **싱글 플레이 전용.** 멀티플레이·네트워크 기능은 범위 밖이며, 관련 구조(서버, 동기화, 네트워크 직렬화)를 미리 고려하지 않는다. 게임 상태는 전부 로컬에서 관리하고 세이브도 로컬 파일로 처리한다.

## 2. 작업 규칙

- **빌드와 실행 결과 확인은 사용자가 직접 한다.** Claude는 코드 분석·수정·설계 제안까지만 수행하고, 빌드나 실행을 임의로 시도하지 않는다. 실행해야만 확인 가능한 문제가 있으면 먼저 사용자에게 알린다.
- **`Game.cpp`는 UTF-8 BOM으로 저장되어 있다.** MSVC는 BOM이 없으면 소스를 시스템 코드페이지로 읽어 한글 리터럴이 전부 깨진다. 이 파일의 인코딩을 절대 바꾸지 말 것. 나머지 소스는 ASCII로 유지하고, 사용자에게 보이는 한글 문자열은 전부 `Game.cpp`에 모은다.
- **예외 — 데이터 파일**: `Data/Sim/*.ggd`(NPC·세력·행동·이벤트 등, STORY_SIM.md 15장)는 한글 문자열을 담으며 UTF-8 BOM으로 저장한다. `Sim/*.cpp`·`Sim/*.h`는 ASCII로 유지하고 한글 문자열을 넣지 않는다. 화면에 보이는 한글 중 스크립트성 문자열(튜토리얼 대사, UI)은 계속 `Game.cpp`에 둔다.
- **렌더러에 새 메서드를 추가할 때 Win32 GDI와 이름이 겹치지 않게 할 것.** `windows.h`가 `DrawText` 같은 이름을 `DrawTextW` 매크로로 치환해 버려서 멤버 함수가 사라진다. (`DrawText`, `DrawState`, `GetObject`, `SendMessage` 등)
- 응답은 한국어, 존댓말로. 간결하고 실행 가능한 형태로.

## 2.1 코드 컨벤션

기존 코드베이스의 스타일을 그대로 따른다. 새 코드도 예외 없이 맞춘다.

**서식**

- 들여쓰기는 **탭**. 공백 혼용 금지
- 중괄호는 **Allman** (여는 괄호를 다음 줄에)
- 한 줄 80~100자 근처에서 끊고, 계속 줄은 탭 하나 더
- 섹션 구분은 `// ---- 이름 ----` 또는 `// ===== 이름 =====`

**이름**

| 대상 | 규칙 | 예 |
|---|---|---|
| 타입 / 구조체 / 열거형 | PascalCase | `ModelPart`, `SpeciesInfo` |
| 함수 / 메서드 | PascalCase | `DrawPerson`, `FloodFillAndSeal` |
| 멤버 변수 | `m_` + PascalCase | `m_WindowSizeX` |
| 파일 스코프 전역 | `g_` + PascalCase | `g_Renderer`, `g_Tile` |
| 지역 변수 / 매개변수 | camelCase | `windowSizeX`, `sx` |
| 상수 | `static const` + UPPER_SNAKE | `TILE_W`, `ATTACK_RANGE` |
| 열거형 상수 | 접두어 + UPPER | `T_GRASS`, `PART_ELLIPSE`, `HJ_TORSO` |

**기타**

- 포인터는 `Type* name` (별표를 타입에 붙인다)
- 익명 네임스페이스 또는 `static` 으로 파일 내부 심볼을 가둔다
- 게임 로직은 `namespace Game` / `namespace Level1` 안에
- **주석은 "무엇"이 아니라 "왜"를 적는다.** 코드를 읽으면 아는 내용은 쓰지 않는다
- 한글 문자열과 한글 주석이 있는 파일은 **UTF-8 BOM** 으로 저장한다. 프로젝트에 `/utf-8` 컴파일 옵션도 걸려 있지만 둘 다 유지한다

### 모델 시스템

- 모델 = **관절 트리 + 파트 목록**. 파트는 관절에 붙고, 관절이 회전하면 자식 관절과 파트가 따라온다
- 뼈의 기본 자세는 관절에서 **아래로** 뻗는 방향. 그래서 파트는 `oy = h/2`, 피벗 `(0,-0.5)` 를 쓰고 회전축이 관절에 정확히 얹힌다. 관절 위로 올라가는 파트는 `oy = -h/2`, 피벗 `(0,+0.5)`
- 색은 파트가 직접 갖지 않고 **팔레트 슬롯 + 명도 배수**로 참조한다. 모델 하나가 플레이어·주민 12명·몬스터를 전부 커버한다
- 빌드는 최초 1회. `Data/models.bin` 에 저장하고 다음 실행부터는 읽기만 한다. **구조체 크기를 헤더에 같이 적어** 파트 구조가 바뀌면 캐시가 자동 폐기된다
- 새 모델을 추가하면 `ModelId` 에 넣고 `BuildAll()` 에 빌드 함수를 등록한 뒤 `CACHE_VERSION` 을 올린다

### 블렌더 아트 파이프라인

- 에셋은 `Art/scripts/*.py` 가 블렌더(bpy)로 **처음부터 끝까지 생성**한다: 메쉬 → 스켈레톤·스키닝·IK → 액션 → 프로시저럴 머티리얼 → 이미지 텍스처 베이크(basecolor / roughness / height / normal / bump) → 쿼터뷰 스프라이트 렌더. 손으로 .blend 를 고쳤다면 스크립트에도 반영하지 않으면 다음 재생성 때 사라진다
- 카메라는 정사영, 회전 (60°, 0, 45°). **1 BU = 1 타일 = 72x36 마름모**와 픽셀 단위로 맞는다 (1배 기준 1 BU = 50.9 px 가로, 수직 1 BU = 44.1 px). 블렌더 X = 게임 wx, 블렌더 Y = -게임 wy
- 뷰 변환은 Standard. 톤 커브·그레이딩은 엔진 `Composite.fs` 가 건다 — AgX/Filmic 으로 구우면 이중 톤매핑이 된다
- 조명은 `ggcommon.light_rig()` 하나를 전 에셋이 공유한다 (화면 좌상단·앞에서 오는 키). 바닥 그림자는 굽지 않는다 — 엔진의 `DrawShadow` 가 그린다
- 캐릭터는 화면 5방향(s, se, e, ne, n)만 굽고 nw/w/sw 는 좌우 반전 (`SpriteAtlas::SpriteDirFromWorld`)
- 스프라이트는 2배(타르투 3배)로 구워 1배로 줄여 그린다. 아틀라스는 밉맵 + 프레임 간 여백 4px
- 캐릭터·몬스터 스크립트는 `G.MATTE = 1.0` 으로 반사광(러프니스·스펙큘러·코트·시인)을 한 단계 죽인다. 음식·환경은 0 (윤기 유지)
- 에셋 목록: 리노·타르투(캐릭터), 토마토마·알감자·방울콩·버섯당(잡몹, 같은 리그), 호수사슴, 집·나무·화덕+솥·요리, 소품 20종(`props.py`). 주민은 아직 SDF
- `Game.cpp` 의 `USE_BLENDER_SPRITES` 를 false 로 두면 예전 SDF 그림으로 돌아간다. 아틀라스를 못 읽어도 자동으로 SDF
- 새 에셋: 스크립트 작성 → 렌더 → `pack_atlas.py` → `Data/Sprites` 갱신 → `Game.cpp` 에서 `FindAnim/FindSprite`

- 깊이는 z-buffer가 아니라 `x + y` 오름차순 정렬(painter)

## 4. 렌더링 방침

**2D 스프라이트 + 좌표 변환식** 방식을 채택한다. (실제 3D 지오메트리 + 직교 투영 카메라 방식은 작업량 대비 이점이 적음)

- 월드 → 스크린 변환
  ```
  sx = (wx - wy) * tileW / 2
  sy = (wx + wy) * tileH / 2 - wz * heightScale
  ```
- 깊이는 z-buffer가 아닌 **y 기준 정렬(painter's algorithm)** 로 그리는 순서를 제어한다.
  → 스프라이트 알파 블렌딩과 z-buffer가 충돌하는 문제를 회피할 수 있다.
- 아이소메트릭 타일은 가로:세로 2:1 다이아몬드가 기본이므로 **비균등 스케일이 필수**다.

### 오픈월드 대응 설계 원칙

- **청크 분할 + 스트리밍**: 월드를 고정 크기 청크로 쪼개고 플레이어 주변만 로드/언로드
- **컬링**: 청크 단위로 화면 밖 배제
- **공간 분할**: 충돌·상호작용 탐색용 그리드 또는 쿼드트리
- **데이터 주도**: 맵·아이템·NPC·재료 테이블을 코드가 아닌 외부 파일로
- **세이브/로드**: RPG 필수

> 스코프 주의: 한 학기 안에 오픈월드 RPG를 완성하는 것은 비현실적이다.
> **버티컬 슬라이스**(지역 1곳, 재료 몇 종, 조리 루프 1회전, 가게 거점)로 완성하고,
> 청크 스트리밍 구조로 "확장 가능함"을 코드로 증명하는 방향을 기본으로 한다.

## 5. 게임 디자인 지침

### 5.1 세계관 전제

**참조 축: 『토리코』의 세계관 + 유럽풍 외피.** 세계가 미식을 중심으로 돌아가는 구조는 토리코를 따르고, 그 위에 이탈리아·프랑스·프로방스의 문화적 외피를 씌운다.

**미식종.** 미식 재료는 마력을 품은 **강력한 야생 생물**이며 「**미식종**」이라 부른다. 원칙은 단순하다 — **강할수록 진미다.** 그래서 최고의 재료는 언제나 가장 위험한 곳에 있고, 재료를 얻는 행위는 채집이 아니라 **사냥**이다.

**먹으면 강해진다.** 미식종을 제대로 조리해 먹으면 그 힘의 일부가 몸에 남는다(시력, 내한, 지구력, 회복). 이것이 사람들이 목숨을 걸고 재료를 쫓는 이유이며, **RPG 성장 시스템과 직결되는 세계관적 근거**다.

**미식이 세계의 중심.** 이 세계에서 미식은 취미가 아니라 경제·명예·권력의 축이다. 귀족은 진미로 서열을 다투고, 상단은 재료 항로를 두고 싸우며, 도시의 부는 그 지역에서 무엇이 나는가로 결정된다. 요리사는 예술가이자 학자이며, 뛰어난 요리사는 영웅 대접을 받는다.

**요리사와 사냥꾼.** 재료를 잡는 것과 요리하는 것은 별개의 기술이라, 이 세계에는 **미식 사냥꾼**이라는 전문 직업이 존재한다. 요리사와 사냥꾼이 짝을 이루는 것이 관행이며, 주인공처럼 둘 다 하려는 자는 드물다.

**시대는 산업화 직전의 근세.** 도시에는 시장·카페·개인 레스토랑이 있고, 도시를 벗어나면 미개척 숲과 산이 남아 있다. 문명과 야생이 반나절 거리에 공존한다.

> 근세로 잡은 이유: 중세에는 요리사가 귀족의 하인이었을 뿐 독립된 직업이 아니었다. "셰프"와 "레스토랑" 개념은 18세기 프랑스에서 성립한다. 요리사를 지망하는 성장 서사는 근세 이후여야 성립한다.

### 5.1.1 미식가 협회와 등급 체계

요리사가 되려면 「**미식가 협회**」의 인증이 필요하다. 협회는 채집 허가증 발급, 남획 감독, 요리사 등급 심사, 그리고 **미식종의 등급 판정**을 담당하며 **게임의 진행 게이트** 역할을 한다.

협회는 모든 미식종에 두 개의 수치를 매긴다. **이 둘은 별개다.**

| 지표 | 범위 | 의미 |
|---|---|---|
| **포획 등급** | 1 ~ 10 | 위험도. 사냥 난이도이자 지역 게이팅의 척도 |
| **미식 등급** | ★ ~ ★★★ | 맛의 격. 요리로서의 가치 |

- 플레이어의 요리사 등급과 대조해 **"이건 아직 무리다"** 를 자연스럽게 알리는 UI 장치가 된다. 레벨 제한 텍스트 없이 오픈월드의 진입 통제가 가능하다.
- 두 수치를 분리했기 때문에 **선택이 생긴다.** 포획 등급 8인데 미식 등급 ★ 인 놈(위험만 하고 맛없음), 포획 등급 2인데 ★★★ 인 놈(안 위험한데 진미 — 대신 서식지가 극단적으로 좁거나 조건이 까다롭다). 위험도와 보상이 일치하지 않는 설계가 탐색을 재미있게 만든다.

### 5.2 톤 & 아트 디렉션

- **유럽풍 판타지.** 이탈리아·프랑스·프로방스 계열이 기준.
- **기준 팔레트는 프로방스·지중해의 따뜻한 톤**(황토, 테라코타, 라벤더, 올리브 그린, 레몬 옐로).
- **북유럽 계열의 차가운 톤은 북부 숲 지역에만 사용**한다. 지역 이동의 체감을 색온도 변화로 드러내기 위한 의도적 대비이며, 전역에 섞지 않는다.
- 쿼터뷰에 유리한 소재를 적극 활용: 붉은 기와 지붕, 석조 벽, 좁은 골목, 광장, 노천 시장. 타일 반복이 자연스러워 배칭에도 유리하다.
- **밝은 톤 유지 규칙**: 사냥이 전면에 나오는 세계관이지만 유혈 표현은 쓰지 않는다. 쓰러진 미식종이 빛이 되어 재료로 변하는 연출을 기본으로 하고, 미식종 디자인은 현실 동물을 그대로 닮지 않게 한다. 포획 직후에는 **감사 의례**를 넣어 "죽였다"가 아니라 "받았다"로 읽히게 한다.
- **재료 연출에 힘을 준다.** 이 세계관에서 가장 중요한 순간은 전투가 아니라 **먹는 순간**이다. 김, 육즙, 단면, 소리. 조리와 시식 연출이 이 게임의 하이라이트이며 여기에 리소스를 우선 배분한다.

### 5.3 주인공과 동기

시골 마을 식당집 아이. 어머니의 부엌에서 자랐다.

주인공에게는 **재현할 수 없는 한 그릇의 기억**이 있다. 아주 어릴 때 단 한 번 먹었던 요리로, 맛은 선명한데 무엇이었는지 모르며 어머니는 알려주지 않은 채 세상을 떠났다. 그 맛을 다시 만들기 위해 요리사가 되려 한다.

> 이 설정이 오픈월드의 엔진이다. 목표가 "어딘가에 있는 무언가"이므로 대륙 전체를 탐색할 이유가 생기고, 지역마다 단서를 하나씩 배치하는 것만으로 메인 서사가 진행된다.

### 5.4 중심 갈등

- **외적 — 남획.** 상단과 귀족이 희귀 미식종을 남획해 씨를 말리고 있다. 미식종이 사라지면 그 지역의 맛도 영영 사라진다. 주인공이 찾는 재료 역시 멸종 직전이며, 두 축은 3막에서 합류한다.
- **내적 — 재현이냐 창조냐.** 그 맛은 완벽히 재현할 수 없다. 거기엔 재료가 아닌 것들(어머니의 부엌, 어린 자신)이 섞여 있었기 때문이다. 성장의 핵심은 **재현을 포기하고 자기만의 맛을 만드는 것**이며 이것이 엔딩의 감정선이다.

### 5.5 3막 구조

**1막 — 출발**
어머니의 식당 운영으로 시작(튜토리얼: 조작·채집·조리). 협회 심사관이 주인공의 요리를 먹고 *"나쁘지 않은데, 뭔가 빠져 있군"* 이라 평한다. 식당을 닫고 항구 도시로 나가 견습 자격을 획득 → **채집 허가증 = 오픈월드 개방**.

**2막 — 편력 (본론)**
네 지역을 자유롭게 오간다. 각 지역은 다음 넷을 하나씩 보유한다.

- 고유한 미식 문화와 재료군
- 스승 격 인물 (기술 1종 전수)
- 남획 사건 (지역 서브 서사)
- **잃어버린 맛의 단서 1개**

단서 4개가 모이면 3막이 열린다. 순서는 자유이나 난이도 곡선상 항구 → 구릉 → 산악 → 북부 숲을 권장한다. 라이벌이 각 지역에 반복 등장하며 항상 한 발 앞서 있다.

**3막 — 귀결**
요리의 정체가 밝혀지고, 핵심 미식종은 남획으로 **마지막 한 마리만** 남아 있다. 어머니가 그 맛을 다시 만들지 않은 이유는 만들 수 없어서가 아니라 **만들지 않기로 선택했기 때문**임이 드러난다.

최종 선택: 잡아서 재현할 것인가, 놓아줄 것인가.
**진엔딩** — 놓아주고 그 자리에서 자기가 모은 재료로 새로운 요리를 만든다. 그것이 개업하는 가게의 첫 메뉴가 된다.

### 5.6 지역

| 지역 | 모티브 | 재료 | 스승 / 기술 | 사건 | 색 |
|---|---|---|---|---|---|
| **항구 도시** | 지중해 | 해산물, 올리브, 레몬 | 늙은 생선 장수 (전직 협회 요리사) / 손질 | 상단의 희귀 어종 남획 | 청록 + 백색 + 레몬 |
| **구릉 농경지** | 프로방스·토스카나 | 허브, 포도, 라벤더, 밀 | 수도원 양조 수도사 / 발효 | 대지주의 토지 독점 | 황토·테라코타·라벤더 **(기준 팔레트)** |
| **산악 지대** | 알프스·피에몬테 | 치즈, 송로버섯, 사냥감 | 사냥꾼 겸 숙성 장인 / 숙성 | 송로 채집권 분쟁 | 회백색 + 짙은 녹색 + 눈 |
| **북부 숲** | 북유럽 | 베리, 야생버섯, 꿀 | 은둔 요리사 / 훈연 | 남획 사건의 진상 | 창백한 푸른빛 + 회색 목재 + 붉은 베리 **(대비 지점)** |

북부 숲이 클라이맥스 지역이다. 은둔 요리사는 주인공이 찾는 맛을 아는 유일한 인물이며, 그가 협회를 떠나 숨은 이유가 남획 사건의 진상과 직결된다.

### 5.7 주요 인물

- **주인공** — 시골 식당집 아이. 기억 속 한 그릇을 쫓는다.
- **라이벌** — 협회 수석 견습. 기술은 압도적이나 *왜* 요리하는지가 없다. 주인공과 정확히 반대이며, 2막 후반 그가 무너질 때 주인공이 답을 준다.
- **동행** — 재료를 냄새로 찾는 작은 짐승(송로 개 모티브). **재료 탐지 시스템 그 자체**로, 서사와 게임플레이가 같은 존재로 묶인다.
- **스승 4인** — 지역별. 손질 / 발효 / 숙성 / 훈연.
- **은둔 요리사** — 진실을 아는 자. 북부 숲.
- **대립 축** — 상단주, 그와 결탁한 협회 간부.

### 5.8 핵심 루프

```
정보 수집 → 포획/미식 등급 확인 → 추적 → 사냥 → 조리 → 시식(성장) → 평판 → 새 의뢰·지역 개방 → 반복
```

등급 확인 단계가 루프에 포함되는 것이 핵심이다. 플레이어는 매번 **"이 위험을 감수할 가치가 있는가"** 를 스스로 판단하게 되고, 이 판단이 오픈월드에서 다음 목적지를 고르는 행위 그 자체가 된다.

가게는 거점이자 세이브 포인트이며, 진행에 따라 메뉴가 늘어난다.
**플레이어의 성장이 메뉴판으로 가시화되는 것**이 이 게임의 성장 실감 장치다.
